Single-player skirmish and campaign. Expect unfinished behavior and compatibility gaps.

Step 01

Buy the game. Bring the data.

Already have Total Annihilation installed? You’re ready for step 2. Otherwise, buy it from GOG or Steam and install it, or use your original CDs.

On Mac or Linux, you can bring an installed Windows game folder from another computer or a Wine/CrossOver installation. Nanolathe itself runs natively. You need the installed game files, not just a store installer or CD image.

Choose the folder containing the game’s HPI archives and installed expansion data. Keep the archives together; there is no need to unpack them.

When you run the Nanolathe installer in step 2, it looks in common Steam, GOG, Wine, and CrossOver locations. If it cannot find your game, choose or enter that folder when prompted. It remembers your choice.

The development reference installation includes the base game, Core Contingency, Battle Tactics, and the 3.1 patch. Compatibility with other combinations is still being established.

The installer downloads the engine and its build tools. Original game data is required separately and is not included.
Step 02

Run the install command.

Open Terminal on Mac or Linux, or PowerShell on Windows, and paste the matching command. The installer downloads Go into its own folder, builds a pinned engine release, and creates a shortcut. You don’t need to install Go or Git yourself.

Mac / Linux · Terminal 
curl -fsSL https://nanolathe.gg/install.sh | bash
Windows · PowerShell 
& ([scriptblock]::Create((irm https://nanolathe.gg/install.ps1)))

The first install downloads the compiler and dependencies, then builds the game. Keep the window open until it finishes. Later launches use the shortcut; there is no rebuild unless you choose an update.

Read the public scripts before running them: Mac / Linux installer · Windows installer. The release manifest records the exact source revision and download checksums.

These are locally built, unsigned alpha releases. Windows may show an app warning; some security configurations block unsigned apps. See Windows launch help.
Supported computers and prerequisites

Mac: Apple Silicon or Intel. Windows: 64-bit Intel/AMD. Linux: x86-64 or ARM64, with a working graphical desktop, graphics drivers, and window-system and audio runtime libraries. Native Windows ARM builds are not included in this first installer.

The installer runs in your user account. It uses its own Go toolchain and cache and does not replace an existing Go installation. Linux may still need runtime packages from your distribution; building with Go does not supply graphics drivers.

Step 03

Use the shortcut to play.

After installation, launch Nanolathe from its app or menu shortcut. The shortcut checks for a newer release. If one is available, choose whether to update and play or keep playing your installed version. If you’re offline, your installed game still launches.

Get the latest tested source release

Choose Update & play when the shortcut offers a new release. It reuses the compiler and build cache, preserves your saves and settings, and keeps the previous working build if the update fails. You can also close Nanolathe and rerun the install command at any time.

Installed the first alpha already? Run the install command once more to add update checks to your shortcut. Future published releases will then be offered when you launch.

Your saved games

The installed launcher keeps new saves in Nanolathe’s own user folder, separate from Total Annihilation. Existing retail saves stay where they are. To bring one across, copy its .SAV file into Nanolathe’s saves folder while the game is closed. Save compatibility is still a work in progress.

Installation paths, logs, manual launch options, and removal instructions are documented in the installer guide.

If something gets in the way.

Windows says “Windows protected your PC”
The usual SmartScreen dialog offers More info → Run anyway. Only continue if you trust the source. Smart App Control and managed-device policies are different: they can block unsigned apps without a per-app override. This installer does not change those settings. See Microsoft’s explanation.
The engine cannot find game content
Choose the installed game folder containing the original archives. If the remembered folder was moved, the launcher will ask again. A corrupt or incomplete installation must be repaired before it can load.
Linux reports a missing shared library
Install the named window-system, graphics, or audio runtime package through your distribution’s package manager. Launch from a working graphical desktop with graphics drivers available.
A download or build fails
Read the error in the terminal, check your connection, and rerun the install command. A failed update leaves the previous build selected.
Something in the game behaves incorrectly
Report an issue with your operating system, installed source revision, and the relevant log or error message. Don’t attach retail game archives. The engine README describes the current limits.

Prefer to build it yourself?

Install Go 1.25 or newer and Git, then run:

Terminal / PowerShell 
git clone {{ site.Params.engineRepo }}.git
cd nanolathe
go build -o nanolathe ./cmd/nanolathe
./nanolathe

On Windows, build with -o nanolathe.exe and run .\nanolathe.exe. Add --root "/path/to/TotalAnnihilation" to select game data explicitly, and --save-dir "/path/to/saves" to choose a separate save directory. Run --help for other options.

Ebitengine 2.10 supports desktop builds with Go alone; no C compiler or development headers are needed. Linux runtime libraries are still required. Read the Ebitengine release notes.
